## F. Binary-staleness guard for the e2e specs (post-review, landed)

Review finding: `requireBinary()` (duplicated in E2eSpec, EngineE2eSpec,
FixtureE2eSpec, MediaE2eSpec, SignalE2eSpec) only asserted the linked binary
EXISTS. `sbt test` compiles sources but never relinks
`target/scala-3.3.3/tail-tones` (only `nativeLink` does), so every
binary-driven spec — byte-identical tee, event goldens, signal/TERM, media —
could silently pass against a STALE binary.

**Decision: IMPLEMENTED (the boring version).** `src/test/scala/tailtones/
BinaryGuard.scala`: before a spec uses the binary, if the newest build input
(`src/main/**/*.scala`, `src/main/**/*.c`, `build.sbt`, `project/*.sbt`) has
an mtime after the binary's, fail with
`binary older than sources — run \`sbt nativeLink\`` (naming the binary, the
offending source, and the drift in seconds). One walk of `src/main`, computed
at most once per distinct binary per run (AtomicReference cache), not per
test. TEST sources are excluded deliberately: they never enter the binary and
`nativeLink` is a no-op when `src/main` is unchanged, so including them would
demand relinks that can never refresh the binary's mtime (unactionable red).

**Container/CI false-red: NOT possible in this repo's flow, so ONE escape
hatch was chosen — `TAILTONES_ALLOW_STALE_BINARY=1` demotes fail → stderr
warning** (documented inside the failure message itself). Justification:
`scripts/devcontainer/verify.sh` runs `sbt nativeLink` (step 1) before
`sbt test` (step 6), and docker COPY preserves host-checkout mtimes, which
are by construction older than the just-linked in-image binary — the guard
passes in-container without any override. The env hatch exists only for
exotic prebuilt-binary setups (e.g. `TAIL_TONES_BIN` pointing at a binary
built elsewhere); warn-not-fail was rejected as a mode because an implicit
container carve-out silently weakens the host default and is ungreppable.

Proven biting (host, this machine): `touch -t 202601010000
target/scala-3.3.3/tail-tones` then `sbt testOnly tailtones.E2eSpec` → every
test fails with
`java.lang.AssertionError: binary older than sources — run \`sbt nativeLink\`:
…/target/scala-3.3.3/tail-tones is 27125740 s older than
src/main/scala/tailtones/Main.scala. Set TAILTONES_ALLOW_STALE_BINARY=1 only
for intentionally prebuilt binaries (container image builds link before
testing).`
Same backdated binary + `TAILTONES_ALLOW_STALE_BINARY=1` → the warning prints
to stderr and 15/15 E2eSpec tests pass. Restored via `sbt nativeLink`
(relinks → binary mtime now postdates every build input — the remedy is a
plain no-op relink), full suite green after.
