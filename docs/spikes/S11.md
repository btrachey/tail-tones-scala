## A. Devcontainer recipe (plan §9 PREREQ) — decisions

- **Base:** `debian:trixie-20250929` (Debian 13, date-pinned snapshot for
  rebuildability). Plan said "Debian + clang/LLVM + libasound2-dev +
  alsa-utils + mpg123"; all five resolve in trixie (clang 1:19.0-63,
  libasound2-dev 1.2.14-1+deb13u1, alsa-utils 1.2.14-1, mpg123 1.32.10).
- **clang 19 DISTRO — Homebrew-LLVM-23 parity NOT needed.** Scala Native
  0.5.12's tested clang range covers 16–19; `sbt nativeLink` links green
  with distro clang out of the box (verify step 1 → ELF aarch64 binary).
  No LLVM-23 backport, no clang flag hacks (contrast S0-F: the plugin bump,
  not the compiler, was the mandatory fix — the container ships 0.5.12).
  `g++` + libstdc++-14-dev are installed because the `clang` meta-package
  only pulls the C side; SN's C++ unwinder bits link against libstdc++.
- **JDK 21 headless + sbt 1.10.6 pinned tgz** (same sbt as the darwin box —
  prompt.md toolchain table; JDK is bootstrap only, plan §2 unaffected).
  JDK 21 chosen: trixie also has 17; 21 matches the host and avoids
  surprises in the sbt launcher scripts.
- **Sources are COPYed, never bind-mounted** (decision: COPY). The container
  `sbt` writes `/opt/tail-tones/target/` inside the image layer — the host's
  darwin Mach-O binary at `target/scala-3.3.3/tail-tones` is physically
  unreachable from the container, so concurrent/`target/`-clobber between
  host and container sbt is impossible BY CONSTRUCTION. `.dockerignore`
  excludes `target/`, `project/target/`, `*.class`, `out.html`, `.git/` so
  darwin artifacts never even enter the build context. `project/` + `src/`
  COPY runs before the warm-up `sbt compile` layer → stdlib link cost lands
  at image-build time; `docker run --rm tail-tones-dev` starts warm.
- **Rebuild is one command:** `docker build -f scripts/devcontainer/Dockerfile
  -t tail-tones-dev .` (repo root), verify is `docker run --rm tail-tones-dev`.
- Extra packages beyond the plan's list: `procps` (ps/pgrep — orphan checks
  in verify.sh + EngineE2eSpec's pidAlive), `ffmpeg` (ffplay for the
  promoted-default smoke + S12's transcode), `file`/`tar`/`curl`/`ca-certs`
  (image plumbing), `g++` (see above). All apt; no new *library deps* for
  the product itself — plan §2 allowlist untouched.

## B. Platform detection + `auto` ordering decision

**Plan §6.1's Linux auto row said "alsa-pipe if aplay else null"; S11 ships
`ffplay-pipe` FIRST, then alsa-pipe, then null+warn. Decision + rationale:**

1. S0-E's promotion condition — "if it plays with acceptable latency, it
   replaces both spawn and alsa-pipe" — has been MET and measured on macOS
   (S10-A: ffplay-pipe pays its buffer once; alternatives pay per-voice).
   alsa-pipe shares ffplay-pipe's exact architecture (same PipeEngine), so
   the choice is buffer-behavior, not code path.
2. ffplay's internal buffering absorbs mixer jitter; aplay's `write()` to a
   blocked ALSA device backpressures our OutputStreamSink (mixer blocks,
   ring fills, drop-newest). ffplay-first gives Linux the same UX measured
   good on macOS, cross-OS symmetry ("one backend, both OSes" — S0-E's
   exact argument).
3. `--backend alsa-pipe` always forces this engine (verified: verify.sh step
   3 runs it explicitly — the aplay child is observed + PCM drains even when
   ffmpeg is installed; PlatformSelectSpec pins "explicit ids never consult
   the platform oracle").

`auto` chain on Linux (Main.selectEngine): probe ffplay (PATH + fallback
dirs) → probe aplay (PATH + fallback dirs) → NullEngine + stderr note
naming BOTH missing binaries and both install hints. Every fallback step
prints a stderr note (never silent, §3). macOS chain unchanged (ffplay →
spawn). Other platforms → null.

**How the code knows it's Linux:** `scala.scalanative.runtime.Platform` —
`isLinux()`/`isMac()` are compile-time constants of the linked binary
(nativelib `platform.c`: `scalanative_platform_is_linux` via `__linux__`).
`selectEngine` takes an injectable `osIs: String => Boolean` oracle
(default `Main.defaultOsIs`) so BOTH branches are testable on either host
(PlatformSelectSpec runs the linux-chain tests inside the darwin binary for
real). The assignment's `javalib os.name` route was verified anyway in the
container — javalib 0.5.12 `System.getProperty("os.name")` =
**"Linux"** (nativib `platform.c::scalanative_set_os_props` →
`add_prop("os.name", uname().sysname)`; probed via a throwaway container
spec: `OSNAME_PROBE os.name=Linux os.version=7.2.12-orbstack-...
os.arch=aarch64`). `Platform.isLinux` is preferred over parsing os.name:
no string/locale assumptions, and it matches what the linker used for GC/libc
selection anyway.

## C. aplay smoke without a sound card — what proves what

Container reality (documented, not worked around): `ls /dev/snd` → **No such
file or directory**; `arecord -l` → **no soundcards found**; `modprobe
snd-dummy` → **FATAL: Module not found** (Docker Desktop/OrbStack run a
custom VM kernel with no modules dir — the plan's suggested `snd-dummy` is
unreachable in this environment class, and even if loaded it would live in
the VM kernel, not reachable via a plain container). So the plan's
acceptance ("aplay child runs and PCM drains", "ALSA null/dummy device
writing WAV") is proven at the alsa-lib layer via the **`file` plugin with
`null` slave**, baked into `/etc/asound.conf`:

```
pcm.!default { type file  slave.pcm "null"  file "/tmp/alsa-out.raw" }
ctl.!default { type null }
```

- **TRAP (measured):** the `file` plugin's `format` key is the file
  *wrapper*, not an open mode — `format "w"` → `snd_pcm_file_open` fails
  `"file format w is unknown"` → aplay exits 1 before reading stdin (the
  first verify run failed exactly this way). Valid values: `none` (default,
  raw frames) / `wav`. The Dockerfile now self-tests the config at build
  time (aplay 2 s of zeros → byte-count check) so a broken recipe fails the
  IMAGE, not the slice.
- **Raw proof (verify step 3):** engine run `-f --backend alsa-pipe` with a
  live-growing log, SIGTERM at 1.6 s: live `aplay` child seen via
  `pgrep -P` (pid 1565), exit 0 after TERM, tee byte-identical, and
  `/tmp/alsa-out.raw` = **121264 bytes** of PCM with nonzero int16 words
  (e.g. 860) — real mixer output (bed/alert renderers), not zeros; 0
  `aplay` orphans after exit. 121264 B ≈ 1.38 s @ 44.1 kHz mono s16le for a
  ~1.6 s window ⇒ the null slave paces aplay in near-real-time (no
  run-away drain, no stall).
- **WAV proof (plan's literal "writing WAV"):** same setup with
  `format "wav"` → `/tmp/alsa-out.wav` begins
  `RIFF....WAVEfmt ` … `01 00` PCM, `01 00` mono, `44 ac 00 00` = 44100 Hz,
  `88 58 01 00` = 88200 B/s, `10 00` = 16 bit, `data` chunk
  `a0 ae 01 00` = 110240 B (file 110284 B incl. the 44-byte header) — our
  exact format emitted by a REAL aplay consuming our engine's stdin.
- **What this does NOT prove:** no hardware timer/DMA/real DAC, no
  underrun/latency behavior of real `snd-card*`. Those remain the plan's
  human step (below). The transport contract S11 owns — persistent child,
  raw s16le stdin drain at our format, EOF exit, TERM cleanup — is fully
  machine-proven here.

**Host loopback (`arecord -l` / `aplay -l`):** darwin host has NEITHER
binary (`command not found: arecord`) — plan pre-authorizes the documented
manual step. MANUAL (real Linux desktop/VM with a card, e.g. `--device
/dev/snd`): `tail-tones -f --backend alsa-pipe some.log` → audible bed +
saw alerts; `--backend auto` on a box with ffmpeg picks ffplay-pipe (stderr
stays clean); Ctrl-C → `pgrep aplay`/`pgrep ffplay` = 0; `speaker-test`-
grade latency: alert onset ≈ ring cadence (10 ms) + device period.

**ffplay-pipe Linux line (promoted default):** verify step 5 with
`SDL_AUDIODRIVER=dummy` (container has no /dev/snd): real ffplay 7.1.5
child observed under the engine, tee byte-identical, exit 0 after SIGTERM,
no death warnings on stderr (sink stayed alive), 0 orphans. Step 5b pins
the whole auto chain at binary level: `--print-events` shows
`kind=engine-start name=ffplay-pipe`; `TAIL_TONES_FFPLAY=/no/such/ffplay`
flips it to `name=alsa-pipe` + the fallback note; empty PATH + both
overrides bogus → `using 'null'` stderr honesty, exit 0.

## D. Linux landings — traps that bit (all fixed, all pinned by tests)

S10 §D said "everything applies equally under Linux's default signal()
(also no SA_RESTART)" — it did, plus two Linux-specific ones:

1. **SIGPIPE kills the TEST BINARY on Linux.** The mixer drains into the
   fake-child stdin; when `stop()`/`killChildren()` kills a `cat`/`sleep`
   child mid-drain, the next `write()` raises signal 13 — and Scala Native
   does NOT ignore SIGPIPE by default, so the whole munit runner died:
   `[error] Test runner interrupted by fatal signal 13` in
   `tailtones.audio.AlsaPipeEngineSpec` (first full container `sbt test`;
   darwin never saw it because E2eSpec's `SIG_IGN` happened to install
   first — a suite-ORDERING accident, and on Linux suites interleave).
   Fix: every child-writing spec installs `signal(SIGPIPE, SIG_IGN)` itself
   (AlsaPipeEngineSpec + FfplayPipeEngineSpec, same idiom as E2eSpec);
   javalib's write then surfaces IOException → the engine's existing
   warn-once transport-dead path (the honest behavior the tests assert).
   Production binaries are unaffected at runtime (Main's reader threads
   already handle EPIPE as exit-1, §3; the audio mixer catches IOException
   by design).
2. **`findUp` walked past `/`.** `d == d / os.up` is false at root in os-lib
   — the next step threw `AbsolutePathOutsideRoot` instead of the actionable
   "linked binary not found" (hit by `sbt test` WITHOUT a prior
   nativeLink — i.e. the container's own dev loop). Both copies (E2eSpec,
   EngineE2eSpec) now stop at `os.root`.
3. **Config-label test relied on a macOS symlink.** `describe()` shortens a
   path under the process cwd; on darwin os-lib tmp (`/var/...`) never
   matched the child's cwd (`/private/var/...`), so the full path leaked
   into the error and the old assertion passed "by accident". On Linux
   tmp == cwd → label is `bad.json` and the assertion broke. Now asserts
   `contains(bad.last) || contains(bad.toString)` — the S7 contract is
   "names the file", basename is the platform-stable invariant.
4. **PcmRingSpec busy-spin starved its own producer under container CPU
   load** (one-time flake: consumer hammered `drain()` on an empty ring
   holding nothing but re-acquiring the monitor; producer never scheduled
   inside `join(5000)`). Consumer now backs off 0.1 ms on empty (mirrors
   the ring's real 10 ms cadence) and the join budget is 15 s. Production
   ring untouched; 3× full container suite + host suite green after.
5. **ALSA `file` plugin `format "w"`** — see §C; the trap failed the FIRST
   smoke (aplay exit 1, 0 bytes) and the fix is baked + self-tested.

## E. Reuse map (what S12/S14/S15/S17 should know)

- `PipeEngine` (new, `audio/PipeEngine.scala`) is the §6.1 "ONE shared
  mixer" made literal: ring + drain loop + master×fade + voice render +
  bedLoop underflow + child/registry lifecycle + stop/fade + killChildren.
  `FfplayPipeEngine`/`AlsaPipeEngine` are ~30-line adapters (`name`,
  `transportExe`, `defaultCommand`, probe). **S15 coreaudio** may extend
  PipeEngine for the drain side but must NOT route its AudioQueue callback
  through PcmSink (§6.7 C-callback discipline — PipeEngine's mixer thread
  can become the callback-side ring filler; sink stays Scala-owned).
  **S17** direct-libasound follows the same adapter shape (replaces the
  child with a sink over snd_pcm_writei).
- **S12:** `setBedLoop` underflow fill + `Wav.read` already work identically
  on Linux (shared code); Linux transcode (mpg123/ffmpeg at startup,
  missing-tool exit 2 + hint) is the remaining §6.5 work; the container has
  both tools pinned. Container rebuild cadence: edit `src/` → `docker build`
  (cache skips to COPY) → `docker run --rm tail-tones-dev` runs link+tests+
  smokes (~2–4 min).
- **S14:** `verify.sh` is deterministic-by-construction (fixed log generator,
  byte-identity via `cmp`, orphan checks via pgrep) — a template for the
  e2e fixtures layer. Host suite count now 464 tests (added:
  AlsaPipeEngineSpec ×13, PlatformSelectSpec ×8); container ran the FULL
  suite 4× green + the verify smokes 27/27.
- `--print-events` unaffected on Linux (verify step 2: tee byte-identical +
  `name=null` events); headless `--backend null` path never touches the
  new code.
