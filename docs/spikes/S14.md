## A. Fixtures — scripts/gen-logs.sh (plan §8 verbatim)

`test-fixtures/{logback,json,logfmt,docker,mixed,storm}.log`, generated by
`scripts/gen-logs.sh` (bash + awk), **deterministic seed**
`TAILTONES_FIXTURE_SEED` (default 1337):

- NO wall clock: timestamps are synthesized from a FROZEN base
  (`2026-11-09 10:00:00` + 100 ms/line) — rerunning NEVER changes bytes.
- Randomness = an EMBEDDED Park–Miller LCG (`rnd()`: `s = s*16807 %
  2147483647`), NOT awk's `rand()/srand()`. POSIX leaves awk's rand()
  sequence implementation-defined; BSD awk 20200816 and gawk empirically
  agree (verified on this machine — same sequence for an integer seed, they
  share bwk's random.c), but a fixture whose bytes depend on that is a
  cross-host time bomb, so the generator carries its own RNG: identical in
  every awk ever written. (Storm needs no RNG at all — integer math only.)
- Content per plan §8's list: logback (§5.3 timestamped shape + raw keyword
  lines), json (level/lvl/severity keys + no-level + nested json-in-log),
  logfmt (level/sev/severity, quoted values w/ escapes, `level=nope`
  fall-through), docker (`{"log":…}` plain + embedded logback + embedded JSON
  depth-1), mixed (all dialects interleaved + ANSI SGR lines + blanks →
  exercises auto latch/memo/fall-through), storm (2000 lines, 49/50 ERROR →
  severity pinned).
- Reproducibility pinned IN THE SUITE: `FixtureE2eSpec` runs the generator
  twice into scratch, asserts run-to-run equality AND byte-equality against
  the checked-in fixtures (so an edited-without-regenerating fixture reddens
  the suite). Level coverage read off the goldens: logback 5 levels
  (debug4/error1/info105/neutral3/warn7 — incl. the keyword-leg raw lines),
  json 5 (2/2/105/4/7 — incl. no-level + nested-json lines), logfmt 4
  (3/2/109/6 — incl. the `level=nope` fall-through line), docker 4
  (1/107/9/3 — incl. depth-1 nested `{"log":"{…}"}`), mixed 4
  (5/113/23/9 — ANSI + neutral + blank lines), storm 1960 error + 40 info.
- Binary-side golden determinism was additionally verified by regenerating
  via `scripts/refresh-goldens.sh` and diffing against an independently
  hand-piped run of the same normalization: byte-identical (6/6).

## B. Headless goldens — normalization contract (documented)

`test-fixtures/goldens/<name>.events.golden` = `--backend null --print-events
-q` stderr over the fixture, normalized (rules live in
`FixtureE2eSpec.normalizeEvent`, mirrored in `scripts/refresh-goldens.sh`,
contract-tested):

- STRIP `t=` (wall clock) and `seq=` from every kept line. seq is ONE global
  counter across all kinds (`Main.Tee`); scheduler kinds' counts vary with
  real elapsed time, so seq is not reproducible even for level lines.
  Per-file ORDER of kind=level lines is still pinned exactly (single reader
  thread ⇒ input order, seq order ≡ input order).
- KEEP: `kind=level` (full `line=` payload), `kind=engine-start`,
  `kind=engine-stop` — the deterministic lifecycle brackets.
- DROP: `mix-tick`, `voice-start`, `alert-start`, `bedloop`, `mute` — counts
  depend on how many real 20 Hz ticks fit between reader start and EOF.
  This timing-dependent half of the contract is pinned **fake-clock-
  deterministically** by `SchedulerSpec`'s goldens (the S9 layer of the same
  stream); storm alert SEQUENCES additionally assert directly against raw
  stderr in the storm-bounds test. So nothing is unverified — it is verified
  at the layer where it is deterministic.
- Golden refresh ("golden refresh task", plan §9 S14 row): two sanctioned
  paths writing the SAME normalization: `scripts/refresh-goldens.sh` and
  `TAILTONES_REFRESH_GOLDENS=1 sbt test`. Goldens are generated ONCE,
  eyeballed (this slice eyeballed level counts + engine brackets + the §7.3
  severity pins), re-pinned only deliberately.
- `sbt test` covers all fixtures: per-fixture test = tee byte-identity (cmp-
  exact vs file bytes) + normalized event stream == golden. 6 goldens, 2642
  lines total.

## C. Storm perf — <5 % CPU at 10 000 lines/min (plan §9 S14 row)

Method (chosen + documented, per assignment): **`/usr/bin/time -l`** on
darwin, measuring the tail-tones process ONLY. The 10 000 lines are paced by
a SEPARATE feeder process (100-line chunks + 600 ms sleeps → ~60 s wall);
feeder CPU is never in the ratio. stdin is a FIFO — no pipe-buffer coupling
distorts either side. Ratio = (user+sys)/real from the -l report.

Measured (this machine, M-series, idle-ish, real binary debug/LTO-none build;
the [S14-perf] line is printed by the test every run):

| run | real | user | sys | CPU% |
|---|---|---|---|---|
| bash prototype (spike) | 61.87 s | 1.32 | 0.31 | **2.63 %** |
| FixtureE2eSpec (full `sbt test`, suite-loaded) | 60.28 s | 1.32 | 0.25 | **2.605 %** |

Margin: gate stays the plan's **5 %**; measured ≈ 2.6 % ⇒ ~2× headroom. The
feeder's `sleep` scheduling noise moves `real` by ≪1 %, and tail-tones' own
CPU is dominated by classification (memoized lines) — the ratio is stable
run-to-run. Flake tolerance: harness sanity assert `45 ≤ real ≤ 180`
(pacing must have happened) so a broken feed can never accidentally PASS the
ratio; the gate itself stays strict 5 %. If a CI host threatens the gate,
`TAILTONES_SKIP_PERF=1` opts out (default ON on the dev host — plan intent is
a real gate, so opt-out is the escape hatch, not the default).

Storm bounds over the FIXTURE (beyond S9's fake-clock pins): the raw stderr
of the real binary over storm.log is asserted to (a) pin
`severity=1.0` in a mix-tick, (b) emit ≤ 7/s × duration alert-starts,
(c) classify exactly 2000 level events. (Observed: severity pins by event
~664, ONE alert-start for a ~190 ms flood — the §7.2 guard + burst gate
doing exactly what §7.3's last row promises.)

## D. scripts/verify-audio.sh — §8 manual checklist, guided

Implements the plan §8 row verbatim (bed consonant, warn detune audible,
error saw cuts through, media loop smooth, alert-only silent when healthy,
afplay orphans=0 after Ctrl-C) plus S12 §G/§H media items (ping-pong seam,
one-time gapless note) and S13 §G items (SIGUSR1 mute toggle, fade-out on
TERM). Structure: 7 guided steps, each = "listen for:" prompt + real binary
run (FIFO-paced stdin, `--print-events`) + AUTOMATED checks: exit code after
TERM, tee byte-PREFIX identity (TERM lands mid-feed — truncation is correct,
prefix-exactness is the contract), required event markers
(`kind=voice-start source=bed`, `layers≥1`, `kind=alert-start`,
`kind=bedloop path=`, `kind=mute state=on|off`, `kind=engine-stop
fadeMs=400`), and `pgrep -x` orphan count **against a startup baseline**
for afplay/ffplay/aplay + the transport-override binaries (a user's music
player is not an orphan). Interactive = ENTER gates each step; `--auto` =
fixed windows for unattended script E2E. Exit: nonzero on any failed
automated check; LISTEN items counted, never faked (mic is TCC-silent, S0 —
human matrix below).

E2E of the SCRIPT (I cannot hear; I verified the machine): run with
`TAIL_TONES_BACKEND=spawn TAIL_TONES_AFPLAY=/tmp/ttfake/afplay
TAIL_TONES_FFPLAY=/tmp/ttfake/ffplay bash scripts/verify-audio.sh --auto`
→ **41 PASS / 0 FAIL**, exit 0, every step reports BOTH "transport children
observed while running (5–30)" AND "orphan children = 0", 7 LISTEN items.
The E2E runs CAUGHT six real script bugs: two-token grep patterns vs raw
`seq=`/`t=` sitting between tokens in un-normalized stderr (all event-marker
checks passed vacuously or failed — fixed to `kind=X .*Y=`); the alert-only
awk policy check had the same adjacency bug; feeder jobs printed "Terminated:
15" into the report (disowned); fakes that `exec sleep` evade `pgrep -x
afplay` (orphan checks were VACUOUS for fakes — now override transports are
matched by command-line `pgrep -f <path>`, real ones by name); a concurrent
`sbt test`'s real afplay children polluted the orphan count (baseline diff
now printed with the count). Fakes are plain `#!/bin/sh\nsleep 45` scripts —
path-matchable, TERM-dieable.

## E. §11 open questions — the S14 calls

1. **Neutral liveliness (plan §11.1): KEEP STRICT-SILENT.** Rationale: (a)
   the S9 goldens pin neutral → weight 0.0, and `--print-events` is THE
   instrument §7.3 promises — changing it re-opens S9/S10/S12/S13 goldens
   and the bed-grid expectations for zero perceptual gain (the bed is a
   600 ms grid at bedGain 0.35 regardless of neutral traffic; §7.3's "calm
   consonant bed" rows are ALL ≥ 0.06 S from info lines, not neutrals);
   (b) a ~0.01 trickle would make severity — and every mix-tick golden —
   depend on how much non-level chatter the user pipes in, which is the
   opposite of the "survivable, log-flood-proof" contract; (c) no evidence
   of "too quiet a bed" exists in any spike (S9 §E, S13 §C): nobody
   reported the bed dead on healthy logs — the bed is time-driven, not
   traffic-driven. If a human matrix (D) ever flags it, the knob is
   `severity.rates.neutral` (config-patchable today, no code change).
2. **Poll-order multi-file interleaving (plan §11.3): DOCUMENTED, policy
   unchanged.** Behavior (from `Main.runPipeline` + `Source.forPaths`):
   one reader thread per file (started in argv order), each polling
   independently at `tail.pollMs` (default 100 ms); lines are emitted when
   their reader reads them ⇒ per-file order GUARANTEED, cross-file order =
   poll order (which thread sees new bytes first at each 100 ms boundary;
   argv order biases thread-start but nothing more). Documented in
   `--help` under `-f` ("multi-file: per-file order guaranteed; across
   files lines interleave in poll order") — the right surface because it's
   where the flag's promise lives; S16 README should mirror it. A named-
   pipe control channel (§11.2 SIGUSR1 alternative) stays parked for the
   TUI; no evidence of demand.
