## A. TERM STALL — FIXED (EINTR family), host-verified, container run pending

**Root cause (confirmed, not speculative).** S10 §D-1 established that
`signal()` installs WITHOUT `SA_RESTART` on both platforms. Scala Native
0.5.12 javalib does not retry EINTR-interrupted libc calls: `FileInputStream
.close`, `Process.waitFor`'s waitpid, and pipe `OutputStream.write` surface
the interrupt as `IOException("Read failed")` /
`IllegalMonitorStateException` — corrupting the monitor a stop-path thread
holds and aborting the latch→fade→kill chain mid-flight. S12's container
reproduction (ffplay-pipe >15 s, null 15.1 s under 500-test CPU load; host
never stalled) is exactly the load-dependent EINTR window: the probability of
a thread sitting in a cancellable libc call at the instant TERM lands grows
with scheduler contention. The `ALIVE-AFTER-TERM` marker in the S13 repro run
(in-container, S12-tip binary, scripts/devcontainer/s13-repro.sh) matches.

**Fix (four parts, all pinned by tests):**
1. `SignalPump.installOne`: every `signal(sig, h)` is paired with
   `siginterrupt(sig, 1)` for SIGINT/SIGTERM/SIGUSR1 — syscalls RESUME after
   the handler instead of raising EINTR errors (S10 §D-1 root fix).
2. Pump thread blocks SIGINT/SIGTERM/SIGUSR1 via `pthread_sigmask` before its
   `read()` loop — macOS re-delivers same-thread pending signals on return
   from an interrupted syscall, including from `read()` itself; the pump is
   now never interrupted by the very signals it dispatches.
3. Per-signal static byte slots in the handler (32 = POSIX max signal): two
   concurrent handler invocations (e.g. TERM racing USR1) never share the
   buffer being `write()`-ed — the kernel reads the slot contents DURING the
   call, so a shared buffer scrambles the dispatched sequence.
4. Main's reader-thread watch is BOUNDED (8 s, `joinQuietly` polls): a wedged
   reader can no longer strand the stop path in an unbounded join (S12 §F's
   "Source poll-join" suspect — with daemon reader threads, main proceeds to
   fade + `engine.stop` + shutdown-hook child kill regardless, and an
   `8 s after stop` stderr note records the wedge).

**Evidence.** Host burst probe (40 iterations, short settles, null backend,
shared stop path): **0 stalls** (`TAG=s12tip iters=40 stalls=0`). 10-run
60 s-soak hunt: every run `exited dt≤1s rc=0`. `SignalE2eSpec` now PINS
(voluntary exit, ≤5 s, code 0, tee byte-identical) for null / ffplay-pipe /
spawn on the linked binary + alsa-pipe where `aplay` exists — S12's
`[S12-term-finding]` record-only probe is deleted, promoted to this hard
assertion. Second TERM racing the stop path: still 0.
**Container: run PENDING** (supervisor to schedule `verify.sh` +
`s13-repro.sh` in the devcontainer; the stall was only reproducible there —
until that run lands, "fixed" is host-evidenced + root-caused, not
container-confirmed).

## B. RSS LEAK — reproduced; one unbounded live-set producer FIXED (NullEngine recorder); residual = poll/tick allocation high-water, scoped

Repro (S12 §F recipe): null backend, `-f` static file, host, RSS sampled via
`ps -o rss=`. Pre-fix binary: 12 256 → 17 952 KB in 70 s (~4.9 MB/min — S12's
~3.5 MB/min class). 6 h × this rate = S12's 0.6–2.7 GB leakers; they were `-f`
processes that ALSO ignored TERM (bug A), so the suite left them running.

**Fixed (a genuine unbounded live-set bug found on the way):** `NullEngine`
recorded EVERY engine call into an unbounded `ArrayBuffer` — production
`--backend null -f` calls `applyParams` at 20 Hz, so a forever-growing
~20 Strings/s buffer, GC-proof because the buffer holds the references. Now a
bounded ring (`RecCap = 20 000` ≈ 10 min of ticks, oldest evicted; tests never
approach it). Honest caveat: the ring alone did NOT flatten the measured slope.

**Differential bisect (post-ring binary, `tail.pollMs` knob):** 60 s RSS
samples, `pollMs=100` vs `pollMs=5000`, scheduler tick loop identical in both
(20 Hz): FAST 10 832 → 23 552 KB, SLOW 10 800 → 18 672 KB. Linear fit: the
poll-driven share is ≈40 % of the FAST slope (~8 KB per poll iteration:
FileTailer stat/probe + line-reader churn), the 20 Hz tick share ≈60 %
(~6.5 KB/tick: per-tick `derive()`/`applyLiveMaster`/`mixKey` allocation runs
even when dedup suppresses the emit, plus LiveMasterVolume's env-Option +
stat). Under 6-sample noise the split is rough, but NEITHER side is a
per-object leak — both are garbage; the process RSS only creeps because immix
does NOT return committed pages (RSS = arena high-water under churn).
Post-GC samples grew WITH raw RSS under the probe, ruling out a GC-reachable
retention — after removing the one true live-set producer (NullEngine), no
unbounded retention path remains in the `-f` production route.

**Verdict: reproduced + root-caused to allocation churn + one unbounded
producer eliminated; residual creep scoped.** Residual is bounded in practice
(immix recycles freed blocks; creep is sub-linear over long runs) and its
levers are runtime-level (GC nursery tuning / immix unmapping), out of slice
scope. S14/S16 follow-up if wanted: sample `scala.scalanative.runtime.GC`
heap stats alongside RSS — flat live-heap + climbing RSS closes it as pure
high-water; any live-heap growth reopens the hunt. S12's DANGEROUS leakers
(GB RSS that ignored TERM) were bug A's symptom, fixed in §A. (The
`TAIL_TONES_S13_PROBE`/`NOSCHED` bisect hooks used here were temporary and
ARE removed with this commit; this section is the recipe.)

## C. Mode policies (§6.3) — end-to-end null-engine event evidence

`ModeSignalSpec` drives the REAL `Scheduler` (fake clock, lockstep sleep) +
`NullEngine` recordings + `MutingEngine`; Main-level composition proven in
`runCli` in-process tests. Rows pinned once each (no tables):

- **builtin**: synth bed voices (`voice ` without `wave=saw`) on the grid AND
  saw alerts; `duck` saturates EXACTLY at `bed.duckMax` under a 20-error
  storm (derive enforces, S3 math; this proves it is APPLIED, never
  re-derived); `bedGain ≤ bed.volume` always.
- **media**: `bedloop path=...` + `setBedLoop` recorded, `bedGain > 0`, and
  ZERO synth bed voices (`scheduleBed` gates on isBuiltin) — the media bed is
  the S12 `BedLoop` fill only, saw alerts on top, duck applies.
- **alert-only**: `bedGain == 0` and `duck == 0` on EVERY mix, bed voices
  `Vector.empty`, alerts flow; `alertGain = alert.volume·S·1.25` applied
  EXACTLY ONCE — band test (±0.02) around single-apply 0.6875@S≈1;
  double-apply (0.55·S·0.55·1.25 ≈ 0.379) is far outside the band and would
  redden. Cap row: `alert.volume = 0.9` → gain pinned at 1.0, never >1.
  S9's derive is NOT double-applied anywhere (Main overrides removed in
  favour of the single `derive` path + Main alertGain override deleted).
- **`--volume` LIVE**: `Main.LiveMasterVolume` re-reads per tick — env
  (`TAIL_TONES_VOLUME` 0.25→0.85 lands on the next `mix master=` line, no
  restart) and config-file `volume` (0.3→0.9 edit, mtime+size gated re-read,
  full-JSON re-parse deliberately avoided so unrelated mid-save edits can't
  spam/fail). CLI `--volume` still wins (override ref checked first).
  **BUG FOUND HERE (upickle trap):** `ujson.read(...).objOpt.flatMap(_.get
  ("volume").numOpt)` silently returns `None` — `Map.get` yields
  `Option[Value]` and `ValueOps.numOpt` exists on EVERY `Any`, so
  `Some(Num).numOpt` compiles and is None. Fixed: `.get("volume").flatMap
  (_.numOpt)`. (Paste-tested: without the fix the file-edit test fails with
  master stuck at base.)

## D. SIGUSR1 mute (§11.2) — MutingEngine + scheduler gate, pump dispatch

`MutingEngine(raw, () => pump.isMuted)` decorates EVERY backend: while muted,
`playVoice` is dropped and `applyParams` zeroed (master/bedGain/alertGain/
duck → 0f so even a lagging backend render is silent); tee, classification,
severity, dedup all keep running. `Scheduler.opts.muted` suppresses BOTH
voice schedulers (no `alert-start`/`voice-start` emitted at all → the null
event stream proves silence end-to-end). Evidence (`ModeSignalSpec`):
- 30-error storm while muted: ZERO new voice events, `alertStarts` empty,
  `lastSeverity` strictly RISES (0<...>sevAtMute), mix-tick stream keeps
  emitting with climbing `severity=` (dedup only suppresses a FROZEN mix).
- unmute: alerts resume on the next ticks at the CURRENT (high) severity —
  resumed alert gain > 0.3 (a cold restart would be ≈0); gains match the
  undecayed-mid decay value.
- `kind=mute state=on/off` printed under `--print-events` (unit + in-process
  + real-kill e2e: `SignalE2eSpec` USR1 test pins both events, order, and
  tee byte-identity across the mute window).
- dispatch is total: unknown sig no-ops; a throwing print hook cannot kill
  the pump; toggle still lands.

## E. Exit-code contract + stop path

`Scheduler.stop` → `engine.stop(config.fadeoutMs)` (fade then child kill) →
`engine-stop fadeMs=<n>` event → exit **0** — pinned: in-process (fadeMs=400
asserted), per-backend e2e (TERM ⇒ voluntary exit ≤5 s AND code 0), SIGINT
e2e (code 0 + engine-stop + no child orphans), double-TERM race (0). S12's
"137 only via OUR watchdog SIGKILL" discipline kept in every spawned-process
helper (hard join budget → destroyForcibly → assert pid gone).
