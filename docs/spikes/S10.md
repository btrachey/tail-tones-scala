## A. PRIMARY BACKEND DECISION — `ffplay-pipe`, not `spawn`

Plan §6.1 promoted ffplay-pipe conditionally ("if it plays with acceptable
latency, it replaces both spawn and alsa-pipe"); S0-D then measured afplay's
per-voice fixed cost at ~10× the plan's assumption. Measured today, same
machine, 160-line paced mixed log, engine `start()`→observable audio-path
event (exec of `target/scala-3.3.3/tail-tones` to first evidence the transport
is consuming voice-rate PCM):

| path | probe | run 1 | run 2 | run 3 | note |
|---|---|---|---|---|---|
| ffplay-pipe | exec → 8820 frames (200 ms) drained into fake-ffplay stdin file | 160 ms | 171 ms | — | one persistent child; steady-state voice latency afterwards = ring drain cadence 10 ms + ffplay's internal ~0.9 s buffer (S0-E) — paid ONCE at startup, not per voice |
| ffplay-pipe (real ffplay) | exec → `pgrep -P` sees the live ffplay child | 118 ms | 136 ms | — | real binary startup incl. our JVM-free launch |
| spawn | exec → first live afplay child exists (i.e. engine start + WavBank build + first spawn) | 1101 ms | 1101 ms | — | bank build dominates FIRST voice only (630 files); later voices pay afplay's fixed cost every time |
| afplay fixed cost | `/usr/bin/afplay -v 0.5 bed-60-g10.wav` (260 ms of content) exec→exit | 1703 ms | 1709 ms | 1710/1706/1706 warm | ≈ **1443 ms fixed overhead per voice** even warm — matches S0-D's cold 1430 ms (afplay re-initializes CoreAudio per exec; warm cache does not help) |

Decision: **`ffplay-pipe` is the primary macOS backend and `--backend auto`
resolves to it** (PATH probe hit); fallback chain auto → `spawn` (ffplay
missing) → `null` + stderr warning — never silent. `spawn` stays fully
implemented per plan §6.6 (it is also the plan-mandated fallback shape and
the reference for S11's alsa-pipe registry pattern).

Why ffplay-pipe wins, concretely:

- Voice-to-audible latency: ffplay-pipe ≈ drain cadence (10 ms) + child buffer
  once; spawn pays ~1.4–1.7 s **per voice**, forever. For an alert-driven UX
  ("hear the error when it happens") that is the product.
- Process churn: 1 child vs one-per-voice (up to ~5 concurrent observed with
  real afplay in run D below), each 1.7 s lifecycle.
- Architecture: ffplay-pipe IS the §6.1 PcmSink seam — the same mixer ring +
  `PcmSink` S11's `alsa-pipe` and S15's `coreaudio` reuse. Spawn's
  WavBank/`afplay -v` path cannot host duck/master changes mid-voice and has
  no Linux mirror.
- The 1.1 s spawn first-voice cost is bank-build; S12 may cache banks across
  runs, but the per-voice 1.4 s can't be fixed from our side.

## D. SCALA NATIVE 0.5.12 SIGNAL/JAVALIB TRAPS FOUND (drive-by, affects S13/S15)

Four distinct bugs surfaced because S10 is the first slice to send real
signals to the linked binary with real children (S8's E2e never signaled;
S9 ran in-process). All fixed; all pinned by EngineE2eSpec + repro scripts.

1. **javalib `Thread.join` is not signal-safe.** macOS `signal()` installs
   without `SA_RESTART`; SIGINT landing while main is parked in
   `Thread.join()` makes the monitor wait return EINTR, and join's
   finally-block then throws `IllegalMonitorStateException: Thread is not an
   owner of this object` — skipping `scheduler.stop()`/`engine.stop()`
   (orphaned children, exit 1). Worse, the monitor is left broken so a later
   join parks FOREVER (observed main wedged in `LockSupport.parkNanos`).
   Fix: `ChildProcess.joinQuietly` — isAlive + `Thread.sleep(20)` poll, no
   monitors — used at EVERY teardown join (Main reader loop, Scheduler.stop,
   both engines' stop paths). S15's AudioQueue callbacks/joins must use it.

2. **`signal()` handler must not touch the managed runtime.** The original
   handler called `AtomicBoolean.set` from signal context; when the signal
   landed mid-GC the process deadlocked (`sample` showed the thread under our
   handler inside `scalanative_GC_yield`). Fix: async-signal-safe **self-pipe**
   (Drepper): the handler does exactly one `write()` of a static byte into a
   pipe created at install time (buffers in a never-closed `Zone.open()`,
   static-field fds — CFuncPtr may not close over locals, SN UB), a daemon
   pump thread blocked in `read()` performs the managed `running.set(false)`.
   Pump thread is daemon; EOF on teardown retires it cleanly.

3. **javalib `Runtime.addShutdownHook` OVERWRITES SIGINT/SIGTERM handlers.**
   `Runtime.setupSignalHandler` (verified in v0.5.12 `Runtime.scala:25-31`)
   registers its own SIGINT/SIGTERM handlers that run hooks then
   `exit(128+sig)` — so a `signal()` install BEFORE `addShutdownHook` is
   silently replaced, Ctrl-C becomes exit 130, and none of our stop path
   runs (measured: 130 + no engine-stop event with child engines; exit 0
   with null where no hook is registered). Fix: `installStopLatch` MUST be
   called AFTER `addShutdownHook` in `runPipeline` (comment pins the
   ordering). S13 (formal SIGINT fadeout / SIGUSR1): same rule — install
   last; note javalib's atexit hook still runs hooks on the normal-exit path.

4. **`ProcessBuilder.Redirect.DISCARD` is WRITE-typed → illegal for stdin**
   (`IllegalArgumentException: Redirect.WRITE: /dev/null cannot be used for
   input` on every non-stdin spawn). Fix: `Redirect.from(new File("/dev/null"))`
   for afplay-style children.

## E. DESIGN NOTES / HANDOFFS

- **§6.1 seam honored:** ffplay-pipe = ONE persistent child
  (`-f s16le -ar 44100 -i pipe:0 -nodisp -autoexit -loglevel error`, S0-E's
  exact argv; NO `-ac`/`-channels` — raw s16le demuxer is mono by default),
  Scala-owned mixer thread drains the pre-allocated 4×4410 int16 SPSC ring
  (§6.7 sizes; drop-newest) → `PcmSink.write(frames, n)`. All synthesis/mix
  lives engine-side (S2 renderers + `Pcm.addInto`/`applyGain`/`scaleSaturating`);
  the child is a dumb DAC. `applyParams` swaps an atomic snapshot (master×fade
  applied at drain time, so mid-voice volume/duck changes land within one
  10 ms chunk). Underflow serves silence (child clock) or the S12 bed loop.
- **playVoice discrimination:** S9 gives no bed/alert flag on the trait call;
  `VoiceMatch.shapeForFreq` identifies alerts by EXACT shape-root frequency
  (F#3/4/5, never in the pentatonic bed pool — S9 contract) with ±octave
  fallback. Waveform is NOT usable (config `bed.waveform=saw` is legal).
  Trap hit during testing: bed-note renders are fixed-length
  (`Notes.DefaultNoteDecayMs`=200 ms), while `Voice.durMs` is authoritative
  only for the descriptor; playVoice trims to `Voice.samplesFor(durMs)`.
  A freq that accidentally matches an alert root renders the 180 ms alert
  instead — test fixtures must use non-root frequencies for bed (588 Hz used).
- **spawn/WavBank (§6.6):** startup pre-render into `os.temp.dir(deleteOnExit)`
  of scale∪scheduler-pool notes × 10 gain buckets × (plain | ducked) + 3
  alert shapes × 10 buckets ≈ 630 files (~300 ms with S2 renderers + S1 Wav
  writer); bucket = `round(g/0.1)`, bucket 0 (silent) never rendered. Ducked
  variant chosen exactly when `duck ≥ 0.99·duckMax` (fully-ducked floor
  state bakes the (1−duckMax) into samples; partial duck rides `afplay -v`
  residual so bucketing stays honest). Registry: ConcurrentHashMap of live
  children + daemon reaper per child; stop = natural-drain budget (fadeMs
  capped 2 s) then `killAll` (TERM→KILL); `killChildren` is the shutdown-hook
  backstop (Main registers it; `ChildOwned` trait added alongside the
  plan-verbatim `AudioEngine`, which stays untouched). Media loop thread is
  real (respawn per iteration + 50 ms anti-machine-gun guard); **S12 replaces
  with ping-pong pre-spawn using in-context afplayStartMs**.
- **setBedLoop (ffplay-pipe):** decodes 44.1 kHz PCM WAVs in-process with the
  S1 reader (stereo→mono via `Pcm.stereoToMono`), loops seam-to-seam from the
  mixer's underflow path (S12 owns ffmpeg transcode for foreign formats/rates
  + crossfade; today foreign rates warn once + silence, spec stored so S12
  can pick it up). spawn path = plain respawn loop (one-time stderr note that
  gapless is coreaudio-only per plan §6.6; S12 tunes ping-pong).
- **S11 (Linux/alsa-pipe mirror):** reuse `PcmSink`/`PcmRing`/`ChildProcess`
  verbatim (`aplay -f S16_LE -r 44100 -c 1 -t raw -` shares the shape; PATH
  probe pattern is `FfplayPipeEngine.probeFfplay`/`PATHEntries`); `tail -f`
  signal tests must go through the linked binary — everything in §D applies
  equally under Linux's default `signal()` (also no SA_RESTART).
- **S12:** start from `SpawnEngine.setBedLoop` loop thread + `FfplayPipeEngine.fillBedLoop`
  underflow fill; afplayStartMs measured here: ~1.4 s fixed (table A) →
  pre-spawn offset for ping-pong = durMs − 1450 ms, min 0.
- **S13:** §D-2/D-3 are your requirements: self-pipe is in place (add signals
  by extending the pump's dispatch, never the handler), and any new signal
  install stays AFTER addShutdownHook.
